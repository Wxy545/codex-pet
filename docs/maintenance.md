# 开发与维护

产品名为 Codex Pet，公开仓库为 `Wxy545/codex-pet`。新安装默认目录为 `%LOCALAPPDATA%\codex-pet`；已有安装可以保留原目录。底层协议、通知身份等兼容标识不随产品名变更。

安装入口从本仓库官方 Raw 地址获取安装器。源码提交查询遇到 GitHub 匿名 API 的 403/429 时，只改读同仓库 `main.atom` 的首条提交，仍按确切 SHA 下载 ZIP；其他错误不切换来源，也不要求用户配置 GitHub 凭据。

## 从源码运行

需要 Windows 和 Node.js 22.12 或更高版本。Codex 模式另需已登录的 Codex CLI；WorkBuddy 模式使用该客户端自带的 CLI。日常安装可直接按 [INSTALL.md](../INSTALL.md) 操作；下面的步骤供修改源码时使用。

```powershell
git clone https://github.com/Wxy545/codex-pet.git
cd codex-pet
npm ci --legacy-peer-deps --ignore-scripts
node scripts/prepare-runtime.mjs
npm start
```

停止桌宠：

```powershell
npm run stop
```

`setup.ps1` 执行依赖安装和运行时准备。首次启动可能下载 Electron，需要能够访问相关下载服务。

## 更新已有安装

`install.ps1` 目前只向新目录安装，不提供原地自动升级。重复运行并指向已有目录会报错；不要删除旧的 `data/` 来绕过检查。源码 ZIP 安装没有 Git 元数据，不能用 `git pull` 更新。

更新前，在旧安装目录关闭跟随启动并停止桌宠：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/disable-follow.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File stop.ps1
```

确认桌宠已退出后，备份旧安装目录的 `data/` 到本机其他位置，再按安装方式更新。

### 通过安装器或源码 ZIP 安装的用户

1. 下载新版源码 ZIP，解压到一个新目录。先准备 Node.js 22.12 或更高版本，再在新目录执行 `npm ci --legacy-peer-deps --ignore-scripts` 和 `node scripts/prepare-runtime.mjs`。也可重新下载安装器，用 `-InstallDir` 指定新目录，并加 `-NoStart -NoFollow`，让安装器准备环境后暂停启动。
2. 从备份恢复需要保留的桌宠偏好、人设和聊天记忆。保留新安装器准备的便携 Node.js 等运行环境，不用旧 `data/` 整体覆盖新目录。旧的 `data/dsh-pet/standalone-runtime.json`、`data/bridge-runtime.json` 是进程与令牌清单，不要恢复；新进程会重新生成。
3. 在新目录启动桌宠，确认设置与聊天记忆正常后，再启用跟随启动：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File start.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/enable-follow.ps1
```

跟随启动会改为指向新安装目录。确认新版可用后，再清理不再使用的旧安装；备份数据不要上传到仓库或 Issue。

### 通过 Git clone 安装的开发者

只有 Git clone 的工作目录可以用 `git pull`。完成上面的停机和备份步骤后，先检查本地改动并处理好自己的修改，再执行：

```powershell
git pull --ff-only
npm ci --legacy-peer-deps --ignore-scripts
node scripts/prepare-runtime.mjs
```

检查相关改动，运行对应测试，再启动桌宠并重新启用跟随。`git pull` 不会替代依赖安装或运行时准备，也不应覆盖未提交的本地修改。

运行时准备也会更新未改动的官方 0.3.0、0.3.1 龙娘包，按已发布文件的 SHA256 识别旧包，只补入新动作和清单。改过清单、媒体或署名文件的自定义皮肤、角色选择和其他本机数据保留。若迁移时恢复了旧角色目录，恢复后再运行一次 `node scripts/prepare-runtime.mjs`。

现在只支持 Q 版。旧版的姐姐版、偶尔变身选择按 Q 版读取；对应角色的 Q 版素材不可用时回到大肥鱼。已有素材文件保留在本机。

### WorkBuddy 安装迁移

当前联动应用保存在 `data/host.json`，角色选择独立保存在 `data/skins/selection.json`。同一源码目录更新后，重新运行 [WorkBuddy 插件安装命令](../workbuddy/README.md#安装)，同步本插件受管缓存；用户编辑过的文件会保留并报错。迁移源码到新目录时，先从旧目录卸载本插件，再在新目录安装，不能复制旧插件连接文件或直接覆盖其它目录的市场登记。

右键「联动应用」切换时，桌宠确认当前没有工作任务，再保存选择并重启自身。切到 WorkBuddy 后，不初始化 Codex CLI 聊天、任务、额度或自动碎碎念；切回 Codex 后恢复这些入口。两种应用同时运行时，只接收选定应用的事件。

## 跟随应用启动

安装器默认开启跟随启动，可用 `-NoFollow` 跳过。跟随器在 Windows 登录后读取所选联动应用，并核对其进程身份；该应用从未运行变为运行时启动桌宠。不修改 Codex 或 WorkBuddy 安装文件，不需要管理员权限。

手动停止桌宠后，同一次应用运行期间不会反复拉起桌宠。跟随启动与桌宠进程分开：停止桌宠不等于关闭以后的跟随设置。

在安装目录关闭跟随：

```powershell
powershell -File scripts/disable-follow.ps1
```

重新开启：

```powershell
powershell -File scripts/enable-follow.ps1
```

### 启动演出

右键菜单和托盘菜单均提供「启动演出」设置，保存在本机 `data/startup.json`。新安装默认 `both`，同时开启桌宠与演出；`pet` 为仅桌宠；`startup` 为仅演出，平时保留托盘入口。已有有效模式保留。跟随器检测到所选应用新启动时，通过现有本机能力令牌队列投递一次启动原因；helper 重建不重播，手动启动桌宠不会在 `both` 模式额外播放。

演出在所选应用所在显示器的独立透明 Electron 窗口全屏播放。Codex 电影为 8 秒姐姐连续镜头，另有约 2.73 秒窗口推进与揭幕；按真实 `video.currentTime`、`ended` 驱动，缺帧或缓冲不会被固定墙钟提前跳过。画面按 contain 等比显示，银灰底填边。玻璃窗按画幅坐标定位，片内生长转正，结束时加速铺满后交回应用。

WorkBuddy 演出只读取卷卷角色包中的待机、工作和招呼三条透明视频，按真实媒体进度衔接，使用暖米色背景和 WorkBuddy 窗口揭幕；素材缺失时跳过演出，不播放龙娘电影。准备运行时按已保存宿主选择素材，WorkBuddy 安装器先保存宿主，再准备角色和演出。

`scripts/bundled-startup.mjs` 将内置影片准备到 `data/startup-media/`，用摘要登记与原子替换维护未改动文件；自定义影片保留，data 根、媒体目录及目标文件的链接均拒绝写入。没有电影文件的旧安装仍可走原 Q 片兼容路径。新电影的关键画面、连续视频和程序音效由本项目制作，素材说明位于 `assets/startup/NOTICE.md`。

真正启动时会短暂等主窗口就绪，渲染器最晚约 21 秒退场，主进程 22 秒 `destroy()` 兜底。「跳过」或 Esc 提前结束，未取焦点的预览只提示按钮跳过。音效使用程序合成的铺底、擦镜、构建、窗口推进与收束；静音只改增益，不暂停音轨时钟。声音错误不截断有效画面。

`src/startup-target.ps1` 只通过已确认的 Codex 进程指纹、窗口几何和响应探测定位主窗口；不读取标题、页面内容或登录资料。实际启动结束时恢复并聚焦该窗口，不移动窗口，不修改 Codex 安装文件。预览不聚焦真实 Codex。电影中的窗口为本地空界面演出，未嵌入真实会话像素。

## 运行时适配

当前依赖固定为 `dsh-pet@0.3.8`，由 `package-lock.json` 锁定。角色、透明动画、随机动作、点击、拖拽、甩抛、菜单与气泡沿用原实现；本项目接入 Codex 会话聚合、额度、CLI 聊天与通知。

`scripts/prepare-runtime.mjs` 从固定版本生成 Codex 宿主入口，调整额度解析，并向桌面壳挂载 Codex 扩展。依赖版本或补丁位置不匹配时会报错停止。安装或升级依赖后需要重新运行准备脚本；需要改补丁时应修改脚本，不只手改 `node_modules/`。

原版蓝色鲸鱼女仆保留 106 段视频动画。白龙娘提供 23 段 Q 版视频、26 条显式动作映射：13 条日常自动候选覆盖待机、转向、两种走位和五类日常动作；点击回应五种，拖拽一种。余额六档、碎碎念三档、工作六档保留事件入口，部分复用已有视频，菜单明确标注共用。合计 34 个动作菜单入口，其中 20 个专属映射、14 个共用映射，不表示 34 段视频。欢迎通过 [Issue](https://github.com/Wxy545/codex-pet/issues) 提供来源、许可和规格清楚的动作视频。

抱书片先制作并核验了四边留白超过 20% 的方形首尾图，再生成一次视频，实际包含轻翻页；透明片保留完整 107 帧。护宝石片的原始尾尖曾变形，最终采用同片正确首帧盘尾做局部合成，翼尖、手、宝石与眼神保持原动画，合格后才接入；不称作尾部动态表演。两条均为 960×960、24fps，进入随机池、点播，护宝石还与余量宽裕档共用。姐姐形象仅用于启动电影，不恢复姐姐桌宠与随机变身。

白龙娘素材位于 `assets/white-dragon/`，许可见该目录的 [NOTICE.md](../assets/white-dragon/NOTICE.md)。卷卷素材位于 `assets/curly-sheep/`，来源与分发说明见其 [NOTICE.md](../assets/curly-sheep/NOTICE.md)。准备运行时复制完整内置包，并为已识别的官方旧包补入新动作。WorkBuddy 新安装默认卷卷，Codex 新安装默认白龙娘；已有自定义素材和角色选择保留。原大肥鱼素材继续遵循 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。

日常动作沿用上游顶层待机、转向、走位、分类动作的权重 `10/5/5/80`，五类权重仍为 `20/20/16/14/10`。上游「时节」是随机池，不是天气或日期订阅。英文界面隐藏原鱼两条含中文字幕的视频，保留龙娘无烘焙文字的招手动作。

龙娘走位使用同一段原生视频驱动画面与窗口位置，起止缓冲各为 0.12 秒；自然结束时补交本次有效走位目标，低刷新也能到达落点。切换角色会取消仍在解码或已经开始的旧角色走位。原鱼继续使用上游视频和时序。

DeepSeek Harness 角色包的安装与数据目录见 [harness/README.md](../harness/README.md)，通过原生 dsh-pet 使用 Harness 会话和服务，不启动 Codex 独立宿主。

## 配置与本机数据

运行数据保存在安装目录的 `data/`，包括桌宠偏好、聊天记忆、本机接口能力令牌和兼容性报告。`data/`、`node_modules/` 和日志已被 Git 忽略，不应加入提交或完整上传到 Issue。

会话联动只读本机 Codex 会话日志；聊天通过 Codex CLI 使用其现有登录状态，适配器不读取或复制 Codex 登录凭据。服务监听本机回环地址，不用于外网或多人共享部署。

| 环境变量 | 用途 |
| --- | --- |
| `CODEX_PET_CLI` | 指定实际的 Codex CLI 可执行文件 |
| `CODEX_HOME` | 指定要读取的 Codex 会话目录根；默认使用当前用户的 Codex 目录 |
| `CODEX_PET_PORT` | 指定桌宠本机服务的起始端口；占用时由运行时选择可用端口 |

Windows 自动定位使用实际的 `codex.exe`。若终端只能找到 `.cmd` 等命令行 shim，可用 `CODEX_PET_CLI` 指定真正的可执行文件。未登录时按 Codex CLI 正常流程登录，不要将令牌粘贴到 Issue、聊天示例或公开配置中。

个性化人设和桌宠偏好留在本机设置中。公开默认值及测试样例不应包含个人称呼、真实会话 ID 或本机路径。

## 状态、额度与聊天

会话状态来自已观测到的本机事件。多个会话先聚合再展示，状态与任务文案应来自同一会话。日志轮转、截断或部分写入不能造成状态串线；旧的完成事件不应在重新启动后当作新通知发送。

占用锁冻结时保留最新工作快照，不切换动画和气泡。解冻后恢复最新的进行中状态及任务文字；若任务已经结束或回到空闲，则清理旧工作气泡并返回待机，不补播冻结期间的完成或出错动画。

额度来自会话日志中的 `rate_limits` 快照，不是持续联网查询的实时账户余额。只显示实际存在且仍有效的窗口，不补造缺失的月度窗口；未提供重置时间时显示“未知”。数据缺失或已过重置时间时，需要在 Codex 主聊天产生新回复后再查看。

余额动画按有效窗口中最高的已用比例分六档：`[0,20)`、`[20,40)`、`[40,60)`、`[60,80)`、`[80,100)` 和 `100%`。气泡进度条另在 70% 和 90% 切换预警颜色。原鱼保留六套档位动画；Codex 独立版龙娘依次共用护宝石、完成、待机、待机、出错、出错视频，不把它们算成六段新动画。

原鱼的三套碎碎念动画保留，龙娘共用打字、思考和招手视频。新安装默认每 600 秒查询额度，碎碎念也默认每 600 秒生成；AI 就绪后先生成一次，后续间隔和开关由 AI 设置控制。碎碎念使用当前角色的人设，切换角色会丢弃旧角色尚未返回的回复。

聊天支持文字和图片。图片入口接收 PNG、JPEG、WebP 的 data URL，校验文件签名、数量和大小；不接受远程图片 URL 或任意本地文件路径。图片只写入本次请求的临时目录，交给 Codex CLI 的 `--image` 输入，完成、失败或取消后清理。闲聊仍关闭操作工具。

操作任务通过独立面板提交，必须先用系统对话框选择工作目录，填写任务并确认本次权限。默认 `read-only`；选择 `workspace-write` 后，以所选目录为 Codex 工作目录，按 CLI 的工作目录写入沙箱执行。工作目录不是文件读取的操作系统隔离边界，读取范围依 Codex CLI 的沙箱策略。此入口不提供全桌面鼠标控制。

聊天和操作任务共用单进程门控，已有请求执行时不会叠加新的 CLI 任务。取消只终止本次 CLI 及其子进程，关闭面板本身不等于取消。

自动碎碎念初始间隔为十分钟，可在 AI 设置中关闭或调整。文字聊天、看图、自动碎碎念和操作任务都会消耗 Codex 使用额度。

## QQ 远程任务

入口位于 Codex 模式的右键与托盘菜单。`src/qq-window.cjs` 负责本机引导和原生目录选择；只允许自己的主窗口调用固定 IPC。AppSecret 只写不读，使用 `src/qq-secrets.mjs` 经 stdin 调用当前 Windows 用户的 DPAPI。QQ 配置、本人绑定、线程映射、近期消息去重及未送达结果保存在 `data/qq-remote/settings.json`，不得分享或上传。

`src/qq-transport.mjs` 使用 QQ 官方 AppID/AppSecret、访问票据和 WebSocket 网关，只接 C2C 私聊文字。票据只在内存；网关确认 READY/RESUMED 后才显示已连接。鉴权错误、机器人未开通权限和平台频控均保留真实失败；消息 POST 不自动重放，也不把被动回复失败静默改为主动发送。QQ 文档中的被动回复时效存在版本差异，实际投递以平台响应为准。

`src/qq-remote.mjs` 先持久去重，再通过共享活动锁提交任务。一个本机配对保存一个独立 Codex thread，修改项目或权限时重建该映射；不接收 QQ 文本中的任意 thread ID。`src/codex-remote.mjs` 使用本机 CLI 的 app-server V2 stdio，线程映射保存成功后才启动 turn；每轮设置只读或工作目录写入权限，网络关闭，不接受扩大权限的请求。审批显示完整有界的操作摘要，过长或疑似敏感内容拒绝远程确认；确认码仅对应当前请求，取消、超时和断连后不再有效。

任务状态直接投影到桌宠；日志观察器排除同一 QQ 线程的重复状态和通知，但保留真实额度观测。任务结果先保存在本机，再尝试回传；中途重启不自动重做未确认完成的任务。`/结果` 分段取回保留内容，不触发模型。私聊之外的群聊、图片及文件接入不属于首版。

Codex 升级后需核对 app-server 方法、命名权限、Windows 沙箱、审批与补充问题的数据结构，以及取消后的进程收尾。QQ 侧需核对鉴权域名、事件权限、发送次数与分片规则。真实验收应使用本人创建的机器人走通配对、续聊、审批/拒绝、取消及回传；模拟平台测试和本机 Codex 验证不能代替这一步。

0.7.0 在 Windows 的完整回归 480/480 通过；随后补充异步显示回调拒绝的隔离检查，远程会话适配窄回归 18/18 通过。真实 Codex 完成四轮模型验证：首次对话、重启桥接进程后恢复同一会话并记住前文、在所选目录写入测试文件、取消正在执行的任务。中英文设置页的隐藏原生检查 21 项通过，包含目录选择、保存后清除密钥输入、复制配对消息及关闭清理。验证使用自建临时项目和合成内容；尚无本人 QQ 机器人，官方 QQ 真实收发与配对留待配置后验收。

## 通知排查

当前联动应用处于后台时，新的完成、错误和待确认事件可触发 Windows 通知；处于前台时抑制重复提醒。Codex 点击跳转需要系统注册其协议，且事件带有有效会话 ID。WorkBuddy 通知只唤起已核实的 WorkBuddy 客户端，不猜测会话深链接。

排查时区分三个结果：通知是否提交到系统、是否出现在通知中心或横幅、点击是否打开对应聊天。通知设置和专注模式会影响显示；前台检查失败时，本次通知不显示。错误日志只保留固定说明及可识别的原生错误码。

先看 `data/app.log` 和 `data/app-error.log`。分享错误时只附脱敏片段或错误码，避免提交聊天正文、完整诊断报告或个人路径。安全问题按 [SECURITY.md](../SECURITY.md) 处理。

## 每日兼容检查

可在 Codex 中配置每天运行的维护任务，同时检查本机 Codex 和原版 dsh-pet：

```powershell
node scripts/check-codex-compat.mjs
node scripts/check-upstream.mjs
node scripts/check-workbuddy-compat.mjs
```

WorkBuddy 检查只读取本项目安装登记中的客户端版本、内置 CLI 版本和本插件文件摘要，不读取登录凭据或会话正文。已验证组合为 WorkBuddy 5.9.3 与内置 `@genie/agent-cli` 2.165.0。版本变化后先核对实际 Hook 事件、插件缓存、前后台检测、跟随启动和通知唤起，再做必要回归；未安装 WorkBuddy 不算故障，读取失败保留旧成功观测并报告 `unknown`。

Codex 检查比较已安装的 CLI、桌面版与上次通过检查的版本，核对 CLI 参数、特性名称和近期会话事件字段，并在需要时运行本地回归测试。报告写入 `data/compatibility-report.json`。缺少日志或版本证据时会记录 `unknown`，不能当作通过；检查不发送真实模型请求。需要对未变化版本重新检查时，运行 `node scripts/check-codex-compat.mjs --force`。

上游检查只访问 [npm 官方元数据](https://registry.npmjs.org/dsh-pet) 和 [原仓库 main 提交](https://api.github.com/repos/PC2005-cloud/dsh-pet/commits/main)，比较最新稳定版、本地依赖和上次已处理的版本及提交。它不使用 GitHub 凭据，不执行 `npm update`，也不自动修改源码。日常未变化时只做两个条件请求，可用 ETag 复用观测，不运行测试或模型请求。

观测与已处理基线保存在 `data/upstream-compatibility.json`，本次报告保存在 `data/upstream-report.json`。报告中的 `candidate` 表示待调查的变更，`unchanged` 表示与已处理基线一致，`unknown` 表示证据不全或检查失败。网络超时、限流或响应异常会保留旧成功观测，不能据此判断没有更新。检查完成的退出码为 0；显式接受被拒绝为 1；检查失败或证据不足为 2。

发现候选后，先查看原版发布内容和提交差异，核对运行时补丁、接口及许可变化。需要升级依赖时，显式修改固定版本和 lock 文件，重新安装依赖并运行 `node scripts/prepare-runtime.mjs`、相关测试及 `npm test`；影响桌面互动、通知或聊天时，再验证对应的实际操作。只有 main 更新、npm 尚未发版时，也应先确认是否影响现有适配。

适配与验证完成后，用本次报告的确切版本及提交接受基线：

```powershell
$report = Get-Content data/upstream-report.json -Raw | ConvertFrom-Json
node scripts/check-upstream.mjs --accept --npm-version $report.candidate.npmVersion --github-sha $report.candidate.githubSha --verified
```

`--verified` 是执行者对已完成验证的声明，脚本不会替代验证。接受时会重新检查两个来源；候选已变化、来源失败，或本地声明、lock、已安装的 dsh-pet 版本未与候选一致时，都不会推进基线。适配失败时保留候选，下次仍会报告，不能为消除提醒而直接接受。

Codex 的 CLI 参数与会话事件可能随版本变化，dsh-pet 补丁也绑定到固定版本。升级后先收集失败证据，再修改适配，完成相关回归和实机验证后提交。

维护者本机配置为每天上午 9 点检查一次，同时关注 Codex 和原版 dsh-pet。该任务不随安装器复制，也不表示其他用户已配置调度。其他用户可按 [中文 README 中的提示](../README.zh-CN.md) 在自己的 Codex 中建立维护任务。

每日维护任务可在发现变化后调查、修改和验证，并在明确授权的仓库范围内提交、推送。未变化时保持安静；验证失败、访问失败或需要人工处理时再报告。调度由 Codex 任务承担，仓库不包含个人账户的定时任务配置。未获授权的本地角色素材不得随功能更新上传。

## 2. 产品目标与用户范围

桌宠首先服务电脑使用者本人：能随手查看任务、从桌面或手机发起操作、看清模型与消耗相关设置，并获得连贯的角色陪伴。内容创作面向普通使用者，允许自行制作角色、动作、启动演出和语音，再自愿投稿。

需要形成的三条体验是：

1. **工作接手**：用户回来后，知道哪些事情等自己处理、哪些已经返回结果，能回到对应会话或打开产物。
2. **连续陪伴**：桌面与本人 QQ 使用一致的人设，按允许范围延续闲聊和共同经历；角色的反应有上下文。
3. **用户创作**：现成素材可导入、绑定、试演、导出，验证后能发起真实 GitHub 投稿，由维护者决定收录。

其他联系人和群聊属于可选的公开互动。默认仍主要供本人使用；开启后，非本人只获得聊天能力，不能因此读取电脑文件、查看私人信息或取得电脑控制权。公开评论区互动保留为后续候选，不等于本规划授权自动批量发评论、加好友或跨平台发布。

## 4. 需求来源与优先级

### 4.1 本轮明确提出的方向

1. 对照其他桌宠查功能缺口，也分析竞品不足和本项目的差异机会。
2. 同时保留实用工具、便捷操作、移动端消息入口和角色陪伴方向。
3. 桌宠本身能直接展开当前任务，显示模型、思考强度和真实进展。
4. 允许不同用途选择模型与强度，简单操作不必使用高成本模型。
5. QQ 可联系角色、发起本人操作并与桌面互动；普通 QQ 小号与 Harness 接入纳入范围。
6. 只有本人能操作电脑；其他人最多聊天，禁止接触电脑文件和本人私人信息。
7. 本地保留记忆细节，以摘要索引和关联记录定位，按需查回，控制上下文及消耗。
8. 用户能编辑和导入角色、动作视频、启动动画、语音包，并通过可视化编辑器验证。
9. 用户验证后可一键投稿 GitHub，由维护者审核决定收录，持续丰富内容。
10. 本次只形成完整规划文档，先不改代码。

### 4.2 优先级定义

| 优先级 | 含义 |
| --- | --- |
| P0 | 发布前必须满足的身份、权限、信息隔离、真实数据和验证要求；相关功能不满足时保持关闭 |
| P1 | 下一阶段核心交付：任务与模型透明、本人 QQ 角色联动、受限记忆、编辑器基本创作链路 |
| P2 | 在核心链路稳定后补齐便捷工具、投稿、声音、内容分发和陪伴细节 |
| P3 | 保留候选；根据真实需求、成本、兼容性和前序使用反馈决定是否实施 |

优先级表示先后与依赖，不代表工期。明确方向可以拆成多个阶段，例如编辑器基本导入绑定为 P1，复杂视频制作是 P3。非本人聊天须先通过 P0 隔离验收，默认不随本人通道自动开放。

## 5. 宠物旁任务列表、进展与交付

### 5.1 入口与展示

在宠物旁提供任务标记，显示运行中及待处理数量；点击直接展开轻量任务列表，保留原点击互动。支持收起、固定展开、按状态／来源筛选及最近完成记录；位置受屏幕边界约束，不抢输入焦点。控制中心承载配置，任务列表承载日常查看。

每条任务展示：项目或任务名称、来源宿主、桌面／QQ 来源、当前状态、模型名称、思考强度、当前阶段、最近事件、本轮耗时与最后更新时间。多任务各自展示模型，不拿某条任务代表全部。只记录展示所需元数据；完整提示词、文件内容、命令正文和内部推理不进入默认列表或 QQ 概览。

当前只接收所选桌面宿主事件；QQ 任务目标另选。规划中的任务视图须标明这两类来源，统一展示不等于同时接管所有宿主或把它们的权限合并。模型和额度也按真实来源区分。

### 5.2 进度表达

- 默认展示“状态＋最近动作＋耗时”，例如读取资料、分析、执行、等待确认、运行检查、整理结果。
- 只有任务提供明确总量时才显示“已处理 3/10 个文件”等真实计数；子项数量不自动换算成工作完成百分比。
- 没有可靠总量，不估算 70% 之类的进度；暂时没有新事件，不直接判定卡死或失败。
- 明确区分“执行返回”“检查通过”“用户确认交付”；模型结束回复不等于验收完成。

### 5.3 操作与结果

复用已有会话跳转、结果复制和任务取消，不另建重复执行面板。根据宿主能力提供返回会话、查看结果、打开产物；只有本系统能可靠控制的任务才显示取消等操作。重试或继续属于新的执行请求，需要核对本人身份、作用域和副作用，取回结果不能重新执行任务。

待处理箱保存需确认、失败和重要完成事项，支持稍后处理、已读／已处理及重启恢复。普通完成通知可合并，待本人处理的事件优先；现有通知前台抑制仍保留，但不能把应保留的待办事项一起消费掉。

交付卡按“实际改动／产物／已做检查／未完成或待决定事项”组织。先覆盖桌宠发起的任务，复用现有结果；外部会话只有状态时继续仅展示状态。后续若接入结果正文，需明确数据来源、读取范围及用户授权，不能依据成功动画编造检查结果。

验收：多个不同模型任务并行不串项；点击返回正确会话；等待状态不会靠计时变成完成；取消、稍后处理、结果留存与重启一致；无真实检查数据时不显示“全部通过”。

## 6. 模型、思考强度与按用途配置

### 6.1 配置范围

| 用途 | 配置要求 |
| --- | --- |
| 固定动作、切角色、显示隐藏、归位、固定提醒和读取已采样状态 | 本地处理，零模型调用；展示“本地操作” |
| 桌面角色闲聊、AI 碎念、QQ 普通问答 | 分别保存模型和强度偏好，可选择较轻量模型；不同入口可显式共用同一策略 |
| 翻译、摘要、图片问答 | 可配置用途默认；图片仅列出支持图片的模型，不把文本模型冒充视觉模型 |
| 文件与开发任务 | 独立模型／强度设置，提交前允许本次覆盖，执行权限另行控制 |
| 记忆整理 | 独立模型与预算；增量、分批整理，不因每条消息重复总结整个记忆库 |
| 语音转写／合成、素材生成 | 使用各自引擎、模型和音色／参数；不把文字模型的思考档位硬套到所有服务 |

优先级为“本次选择 → 用途默认 → 当前宿主默认”。“跟随默认”是显式选项，不表示跨宿主回退。设置变更影响后续请求，运行中请求保留原设置；手选失效、能力不匹配或目录无法确认时暂停并提示，不能静默升级到更贵模型。

模型选择与权限独立。当前 Codex QQ 的“聊天档”仍可能持有项目文件权限，新增非本人纯聊天必须另走无电脑工具的路径，不能仅把模型调低或把模式名称改成“聊天”。QQ 是渠道，不应把所有 QQ 消息都固定为低档或高档。

### 6.2 展示规则

| 信息状态 | 展示规则 |
| --- | --- |
| 空闲 | “闲聊默认：模型名称·强度”，标明只是默认配置 |
| 发出请求但尚无回合确认 | “请求设置”，不提前写成实际生效 |
| 已启动回合确认 | 显示本回合确认的模型／强度，并保留确认来源 |
| 宿主未提供字段 | 显示“未获取”或“宿主未提供”，不用全局默认补齐 |
| 模型不支持强度 | 显示“不适用”，隐藏不支持的选项；不写成“低” |
| 宿主只给自动设置 | 显示“跟随宿主／自动”，不编造一个具体档位 |

思考强度是调用配置，不是对模型内部思维量的测量。运行时只能确认请求或宿主返回的设置，供应商内部路由未知时不作更强声明。结果详情可查看本次模型、强度、用途及可获得的用量；没有定价和账务依据时不推算余额或声称确定节省金额。

### 6.3 三宿主接入

- **Codex**：复用 model/list 及现有模型、思考档位和默认信息，另核实并补齐当前尚未投影给调用方的模态信息；QQ 两档策略已存在，需要扩展到其他用途与任务列表。现有远程显式模型／强度／权限可能影响该原生会话后续默认值，实施时须明确提示并验证，不能声称绝无影响。
- **Harness**：原生默认选择和 LLM 服务有模型及强度基础；原生宠物已有 chatModel／whisperModel 分开配置，部分调用会关闭思考或回落默认模型。需记录实际解析及回落后的设置，再接统一配置；这些能力不代表当前 QQ ACP 已允许逐次覆盖。沿用自己的 profile、服务商、账号与余额。
- **WorkBuddy**：事件与当前 ACP 尚未提供可信逐次模型／强度目录和覆盖通道。字段保持未知或跟随原生，不提供假选择器，不转发给 Codex。需单独验证官方支持及当前客户端版本。

外部既有会话默认只观察真实设置，不应用桌宠闲聊默认。用户明确从本人入口提交新回合或调整后续设置时，才按宿主支持执行。多会话及不同宿主记录不能相互覆盖。

验收：模型列表动态变化、模型失效、无强度模型、图片不兼容、任务中更改默认、多任务并行、原生回落和返回值缺失均有明确结果；本地互动不启动模型请求。

## 7. QQ、移动互动及权限隔离

### 7.1 连接与使用范围

保留官方机器人和普通 QQ 小号两种接入。官方机器人使用平台 AppID／AppSecret；小号由 NapCat 登录并经 OneBot 收发，人设、模型和记忆在本项目或所选宿主中处理。NapCat／OneBot 的消息类型清单不等于宿主识别能力或项目已完成能力。

复用当前本机准备、扫码、连接诊断、配对与六组隔离配置。QQ 接入模式和任务目标继续独立于桌宠角色及本机联动应用。电脑和对应服务需要在线；显示“服务已启动”“QQ 已登录”“连接已鉴权”“本人已配对”时分别使用真实证据。

个人号接入需考虑登录校验、掉线和账号风控，不能承诺长期在线或不受账号限制；作为用户主动选择的通道，沿用指定 NapCat 版本的原始分发和许可边界。

### 7.2 权限矩阵

| 能力 | 已验证本人私聊／本机受控入口 | 其他联系人 | 群聊／公开互动 |
| --- | --- | --- | --- |
| 角色聊天 | 允许 | 本人显式开启后允许 | 本人显式开启后允许 |
| 记忆 | 本人记忆及明确授权的范围 | 仅该联系人与角色的记忆 | 仅本群／当前公开会话的记忆 |
| 项目、任务列表、真实模型设置及系统状态 | 按当前授权可查 | 禁止查看本人的工作及电脑信息 | 禁止公开展示私人工作信息 |
| 任意电脑文件、目录、屏幕、剪贴板、凭据 | 仍受所选目录、用途和权限限制 | 禁止 | 禁止 |
| 命令、文件操作、应用启动、锁屏等电脑控制 | 仅在明确授权和宿主支持范围内 | 禁止 | 禁止；本人在群内提出时转本人私聊 |
| 点播动作、切角色、显示隐藏、修改模型／人设等控制 | 按允许的固定动作或配置操作 | 禁止控制；可有普通聊天带来的角色表现 | 禁止控制；可有公开聊天表现 |
| 配对、修改主人、提高权限上限 | 仅本机受控配置流程 | 禁止 | 禁止 |

聊天产生的表情、短回应或预设动画，是程序的表现性输出，不向外部发送者提供任意动作控制、脚本、URL 或配置修改接口。只有本人能主动点播、切换角色或改变运行状态。

### 7.3 后端必须保证的边界

1. 身份来自可信 QQ 事件字段，按接入方式、登录账号及发送者区分；官方 openid 与个人 QQ user_id 不能猜测互换。昵称、转发内容、引用消息和“我是主人”不能改变身份。
2. 非本人请求在后端分流到固定的纯聊天生成路径，根本不创建电脑任务 Agent，不提供工作目录、文件、命令、MCP 或桌面操作工具。前端隐藏或人设禁令不能替代后端拒绝。
3. 检索记忆由受限程序执行，只返回该身份允许的文本；不能以“记忆在本机”为由给模型任意文件读取能力。主人私人信息也不混入公开人设、共享摘要、工具描述、错误或日志。
4. 角色聊天、工作任务和审批分别处理。只有当前本人、当前任务的一次性确认有效；聊天回答、旧消息、群中引用和模型输出不能变成审批。
5. 保留去重、取消／超时清场、来源绑定、账号变化断开和结果留存。读取保留结果不重做任务；普通消息不会悄悄扩大目录、模型权限或联系人范围。
6. OneBot 和管理入口保持本机回环及独立鉴权。NapCat 原生配置含明文令牌的事实须如实说明，凭据不进素材包、投稿、模型提示或渲染器。
7. 他人聊天、群聊和公开模式默认关闭，可随时停止回复；设置频率、消息量、单次输出和模型预算限制，避免公开互动耗尽本人额度。

### 7.4 本人手机与桌宠互动

本人闲聊与当前角色绑定是首批目标；固定互动建议从手机动作点播、投喂动画、显示隐藏、切角色、归位和简单桌面留言中选择接入，未选项继续保留候选。动作只从当前角色的真实目录选择，没有对应动作时明确反馈；投喂先对应现有动画，不附加饥饿／生病系统。

普通聊天只生成一次回复，同一结果回到 QQ 并投送桌宠气泡；固定动作不另调模型。回执区分已收到、已受理、播放中、已完成及失败；电脑离线或角色没有播放时不能回复“已经做了”。回复与动作关联同一次消息，避免自发消息回环、双回复和重复扣用量。

本人可选择让桌面与 QQ 闲聊共用一个角色记忆范围；多联系人不能复用同一份本人历史。Harness 模式使用其原生服务和角色入口，不绕回 Codex；当前原生聊天接口不带 QQ 联系人范围，若开放多人必须先增加隔离层。项目任务继续使用独立工作会话，不能把闲聊送进当前开发线程。

### 7.5 后续移动能力

- 图片、文件和语音从手机投递到专用收件箱，桌宠提示已收到，允许本人继续处理；电脑产物可以按本人明确选择回传。
- 手机发送链接、便签、待处理事项或定时提醒；保留来源和投递状态。
- 复用现有状态、项目／会话选择、取消、审批及取结果，再提供与桌面任务列表一致的摘要。
- 重要完成／失败／待处理事件可按本人设置回 QQ；须核实官方机器人回复窗口、主动消息权限、频率和 NapCat 实际行为，不能承诺任意时间无限主动推送。
- QQ 语音、短视频、动态角色动图／音频回传分别核对传输、识别、生成和播放能力，不把任何一层支持当成端到端完成。
- 手机独立客户端、多人群聊、其他平台评论互动另列后续任务；不通过本规划自动开启。

验收至少包含：伪装主人、转发／引用审批、非本人直接调用后端、跨账号和跨群查询、过期确认、重复投递、群中电脑控制、恶意路径、消息内指令注入、停止公开回复和预算耗尽。非本人对文件和电脑控制的拒绝必须在实际工具调用前发生。

## 8. 本地记忆网络与上下文预算

### 8.1 当前缺口与目标

锁定版原生 dsh-pet 按角色包条目和宠物实例保存聊天原文，每次只带最近窗口；独立聊天面板也限制近期消息。它们不是已实现的联系人长期索引。多人直接复用同一宠物记忆会混入不同人的对话。

目标是在本机保留可回查的细节，用摘要、关键词和关联关系定位信息；每次只把必要内容交给模型。摘要可以重建，不能靠反复压缩摘要永久替代原文，也不承诺永不遗忘或检索永不遗漏。

### 8.2 存储与关联

| 层次 | 内容与规则 |
| --- | --- |
| 角色公共资料 | 可公开的角色身份和表达风格，不含主人地址、项目、私聊或私人偏好 |
| 近期上下文 | 当前话题最近若干消息，按 token 预算截取，保留问答关系 |
| 摘要索引 | 主题、实体／关键词、时间范围、来源记录 ID、所属范围、确认状态及关联记录 |
| 原始细节 | 带发言者、时间和来源的原文／事件；明确哪些是用户自述、推断、确认或已被纠正 |
| 关联关系 | 人物、事件、项目的相关记录，以及补充、纠正、替代关系；每次跳转重新校验访问范围 |

第一版可用本地文件／本地数据库、摘要索引和全文检索实现。根据真实漏查情况再评估语义检索和多跳关系；“记忆网络”不要求先引入图数据库或云端知识库。

### 8.3 范围隔离

记忆范围由后端绑定的宿主／profile、QQ 接入账号、本人／联系人／群、角色及明确关联的项目确定，模型不能自行填写其他身份或路径。原文、索引、摘要、缓存、关联边和附件引用必须遵守相同范围。

本人私人记忆、每个联系人私聊、每个群的共享记忆分开。群聊不检索成员私聊，跨群不互通，其他联系人不能查询主人信息。群记忆保留发言者；不能把一个人的发言归到另一个人名下。本人 QQ 与本机闲聊是否共享，由本人显式选择，不能因角色相同自动合并全部来源。

公开会话检索不到的记录，连标题、索引条目、命中数量和存储路径也不能泄露。索引查询先做范围过滤，再做相关性筛选；不能先全库检索再希望模型忽略私人结果。

### 8.4 读取与整理流程

1. 程序确定身份、会话范围和本轮用途，检查模型及预算。
2. 带入少量角色设定、允许的必要偏好和近期对话。
3. 在允许范围内查相关索引，按主题、关键词、时间和来源定位。
4. 需要具体措辞、日期、旧决定等细节时，读取少量相关原文，并带上必要背景；找不到依据时说明未查到，不凭摘要补造。
5. 给模型的上下文由人设、近期消息、相关索引和命中片段组成；分别限制片段数及总 token，给问题和输出留空间。
6. 新原文直接落盘，摘要分批增量更新；记忆整理可以使用独立轻量模型，不每轮重写全库。索引增长同样受读取预算限制。

历史记录和摘要都是资料，不能成为当前指令或权限来源。第三方“主人住在某处”一类说法最多留在其自身会话并标为自述，不能改写主人已确认资料。新纠正保留与旧记录的替代关系，回答优先采用当前有效说法。

### 8.5 用户管理与信息去向

本人可查看记忆、来源和本轮选中的片段，可纠正、删除、清空、设置保存期限和导出。删除同步处理原文、索引、摘要、缓存及附件引用；重建索引不能恢复已删除内容。联系人只管理自身范围，不能清除别人的记录或整个群。

删除或撤销范围后，使用旧记忆版本的整理和检索结果失效，不能再次写回。尚未发出的排队请求／回复重新检查允许内容，必要时重建上下文；已经发给外部模型的内容不能靠本地删除撤回。验收加入“整理过程中删除”和“排队回复前删除”，检查旧结果不会把已删记录重新保存。

本地存储不等于不出电脑。检索后选中的片段可能发送到当前模型服务，界面应说明并提供“本次使用的记忆”；公开回复不携带本机路径、凭据或主人私有片段。对话／记忆导出单独授权，不与角色包导出或 GitHub 投稿混在一起。

验收使用合成数据：旧细节回查、否定与纠正、同名联系人、跨群隔离、长会话预算、删除后再查、摘要错误／缺失、检索无命中及提示注入。比较正确率、单轮读取量和实际调用消耗，不只比较压缩率。

## 9. 素材库与可视化编辑器

### 9.1 用户创作流程

统一入口按“新建或复制角色 → 导入素材 → 绑定动作 → 调整效果 → 添加声音／启动片 → 整套试演 → 保存或导出”组织。角色、动作、声音、启动片分别可替换，也能打成整套作品；启动主题仍可独立于角色和真实联动应用选择。

允许新建自定义角色，不限制为内置三只。角色名称、公开人设、封面、素材和动作资料可编辑；至少有可用形象或待机素材即可开始，其他动作逐步补充。内置角色可复制成用户版本，原版保持可恢复；用户改动、原文件和安装随带内容分别管理，升级保留自定义内容。

已有 Q 版桌宠与姐姐启动电影的分工继续保留；新增用户导入能力不等于恢复内置姐姐桌宠选项或随机变身。更换角色也不改变实际宿主、QQ 主人、项目权限或账号。

### 9.2 编辑能力与分期

| 内容 | 编辑与预览要求 | 分期 |
| --- | --- | --- |
| 形象 | 导入图片／图集／受支持视频，调整显示尺寸、位置、落脚锚点和点击区域，检查实际比例与透明边缘 | P1 |
| 动作 | 从当前真实目录绑定待机、点击、拖拽、行走、思考、工作、等待、完成、出错及日常动作；同一素材可共用，明确标记 | P1 |
| 视频 | 选择起止片段、单次／循环、播放频率，检查首尾衔接及切换；深浅／棋盘背景检查白边、绿边、裁切和部件完整性 | P1 基础调整 |
| 事件与台词 | 配置允许的触发条件、短台词、间隔和冷却；与动作配合，不能通过文本配置取得电脑执行权限 | P1 固定事件；P3 扩展行为包 |
| 启动演出 | 复用已有导入库，增加重命名、基础裁剪和声音选择；片段排序、组合过渡逐步扩展，保留跳过／Esc／超时退出 | P2；复杂时间轴 P3 |
| 事件语音包 | 导入录音、试听，绑定招呼／点击／完成／错误等固定事件，设置音量、静音、冷却及是否打断；视频原音和语音避免重复播放 | P2 |
| 一键试演 | 模拟点击、拎起、工作、等待和完成，核对动作、气泡和声音；区分播放器受理与实际播放结束 | P1 动作／气泡；P2 声音联调 |

动作视频优先沿用透明 WebM／PNG 图集基础。普通 MP4 可用于启动电影，不应直接声称具有透明角色效果；导入时先说明支持能力并验证实际解码。透明检查与格式转换分开，遇到不支持格式明确报告。

简单纯色背景处理可以作为编辑器后续增强；复杂自动抠像、补帧、自动修复循环、多轨剪辑、AI 图像／视频生成列 P3。普通素材装配、预览和导出在本机完成，不消耗文字模型额度；可选 AI 制作须显示所用模型及参数，并按用途配置。

### 9.3 语音的两种能力

录音语音包只播放固定台词和提示音。任意聊天回复朗读需要独立的 TTS 引擎／服务、音色、语速和音量；语音输入需要转写。这三项分别启用、配置和验收，不能导入几条录音后声称能够朗读任意文字。声音克隆、实时通话和常开麦克风不列首批。

### 9.4 作品包与更新

作品包包含版本、名称、作者、来源、许可、公开人设、预览、媒体、动作映射、声音及可选推荐启动片。支持单动作、语音包、启动片和整角色投稿；用户不用补齐所有内容才可导出。

包采用允许的媒体和声明式数据，不包含脚本、命令、凭据、QQ 绑定、模型账户设置、私人记忆、日志或本机绝对路径。不自动访问外链补素材，不允许路径穿越和覆盖其他角色。重复 ID、缺素材、坏媒体、超限和版本不兼容均显示具体结果。

导入先预览，保存采用可撤回的用户副本；移除不删除原始文件。导出前列出将包含的文件，可选择是否含语音、启动片和制作源文件；保留每种素材自己的许可，不统一改成 MIT。新增目录与动作注册复用现有实际目录生成和校验机制，不复制维护另一份完整动作表。

验收：导出后在干净数据目录回导，角色、动作、绑定、声音和启动设置一致；升级和卸载保留约定的用户内容；恶意包、坏媒体、缺失资源不能触发命令或访问越界文件。

## 10. 用户投稿、审核与内容分发

### 10.1 投稿流程

目标是“本地检查 → 用户完整试演 → 填来源与公开授权 → 预览投稿内容 → 首次 GitHub 授权 → 一键提交 → 查看审核状态”。用户始终可只在本机使用，不因保存或导出自动公开。

自动检查负责文件、清单、解码、大小和绑定完整性；用户确认透明效果、循环、声音和表现；维护者审核来源许可、角色一致性、实际运行及是否收录。三层结论分开，不能把本机检查通过写成版权确认或正式收录。

### 10.2 真正一键的提交路线

选择“在用户自己的 GitHub 副本中准备投稿分支，再创建 PR”的路线。首次用户完成适合桌面应用的 GitHub 授权，之后由编辑器完成上传与 PR 创建；用户不用手工使用 Git。只请求投稿所需权限，客户端不内置维护者凭据或应用私密密钥。

小型素材可直接放投稿分支；较大视频包按 GitHub 当前容量和 API 限制，上传至投稿者自有仓库的 Release 资源，PR 携带清单、预览、检查报告、版本及摘要。上传路径、文件上限、授权范围和普通外部用户的完整链路须先做验证；不能将超大视频无限提交到主仓库历史。

GitHub CLI 的 Issue 附件上传有目标仓库写权限和类型限制，不能假定普通投稿者可自动将任意 ZIP 上传到我们的 Issue。已有手工 Issue 投稿继续保留；只打开预填页面或让用户手工拖附件，应称“一键发起投稿”，不能作为真正一键上传完成的验收结果。

### 10.3 投稿材料与状态

自动生成作品名称、类型、适用角色、动作／语音／启动内容清单、预览、制作工具、来源许可、适配版本和检查报告。原有规范要求的参考图来源、生成工具／模型和提示词等保留；提交前用户可检查制作资料，移除个人信息。授权必须覆盖项目实际分发及必要适配，不用一个勾选框代替第三方权利证明。

预览、检查报告、PR 清单和上传包绑定同一内容摘要。修改或补交素材后旧检查结果失效，需重新验证；每次下载核对实际包摘要，维护者只收录本次真实复验过的版本，不能凭可变链接或旧报告放行。

编辑器“我的投稿”关联真实 GitHub 地址及版本，显示待审核、需修改、已收录、未收录。修改更新同一投稿，保留讨论；状态来自真实 PR／维护者审查，不由本地按钮自行宣布通过。网络中断可恢复或重试，已提交内容不重复创建；上传部分失败不能显示全部成功。

投稿会公开，未收录也可能仍留在公开 fork、PR 或附件记录中；提交前明确这一点。撤回关闭投稿不等于互联网上所有副本已删除。角色包导出只包含用户选定的作品，绝不自动附加聊天、记忆、账号、源码目录或完整 data。

### 10.4 审核与收录

维护者先检查来源及许可，再检查透明、构图、角色一致性、循环、动作衔接、声音和 Windows 实播。审核流程只处理素材及声明数据，不执行投稿包内脚本，不向未审内容提供仓库密钥或自动合并权。

通过后由维护者校验并保存确定版本的正式素材，不能长期只依赖投稿者随时可改／删除的临时下载链接。保留作者、许可、版本和修改说明。

收录分两层：官方审核素材库供按需下载，少量精选素材随安装默认提供。审核通过不等于全部进入安装包。作品展示、在线社区、商城和自动 Release 属后续决策，本规划不授权创建仓库、发布内容、合并投稿或发送通知。

验收：首次授权、普通外部用户投稿、不同大小作品、断网重试、重复提交、补交版本、需修改／拒收、公开说明、资料脱敏、正式素材下载及回导；必须取得真实可访问的投稿地址。

这些方向在讨论中保留，按高频场景逐项验证，不一次建设通用工具大全。

文字识别、格式粘贴、通用启动和窗口排布已有成熟系统／PowerToys 能力，可评估调用或联接。桌宠重点减少操作步骤和衔接助手，不默认重建完整截图、剪贴板、笔记、文件管理或运维软件。

## 12. 陪伴表现、轻养成与低打扰

### 12.1 低打扰与连续反应

在现有隐藏、全屏和前台抑制基础上，增加时段勿扰、睡觉／唤醒、重要事件优先、普通事件合并、稍后处理和回来后的未处理概览。是否隐藏、停止闲聊、暂停声音、停止模型调用和继续接收本人任务分别定义，不能一个“睡觉”开关暗中取消工作任务。

连续输入、全屏或多任务繁忙时减少闲聊和走动；只有必要信号参与判断，不记录键入正文。角色反复遇到同一故障、用户处理完确认、用户离开后回来时可有连贯后续反应。不同角色的语气、动作节奏和出现频率体现性格；现有“状态映射不同视频”本身不重复计为新增。

### 12.2 共同经历与轻养成

记录有来源的共同工作天数、完成专注、用户确认的项目交付／第一次发布等事件，可解锁动作、台词、纪念物或配饰；例如龙娘书中新增记录、小羊留下纪念物。完成记录不是质量认证，聊天里自称发布也不自动当作已验证成果。

等级、亲密度、成就可选，不以 token 越多越好作为主要奖励；离开几天不默认掉好感、生病或产生照料惩罚。完整饥饿／口渴／健康／金币经济系统保留为 P3，不列核心使用负担。经历记录复用受限记忆及删除机制，私人里程碑不展示给他人。

### 12.3 后续互动候选

- 打字时陪着工作、停止后休息、鼠标靠近回应、抚摸、追视等；区分输入活动状态与采集按键内容，默认不做键盘记录。
- 窗口顶部坐下／行走／跳窗、跟随窗口几何、屏幕边缘探头；与已有屏幕边界、任务栏和跨屏物理分开，不主动移动用户窗口。
- 多宠新增删除、按项目／会话分宠、角色相互动作和碰撞；复用底层，不因支持多窗口就声称已有完整管理体验。
- 稀有动作、时段行为、节日招呼、随机出场、小型反应／记忆游戏、配饰和外观解锁；尊重用户开关、冷却和资源预算。
- 陪伴时长、完成事项、提醒处理和按项目用量历史；只使用真实可得数据，和即时 CPU／内存／GPU、额度条区分，不为了排行榜记录额外私人内容。

## 13. 扩展范围与竞品参考

### 13.1 差异机会与非首期范围

任务监控、多宠、审批、续聊、养成、素材编辑都已有竞品。后续宣传以真实交付为准，不把这些单项称为首创。优先验证“回来就能接手工作”“出现的动作有原因”“记得一起完成的事”“用户可创作和贡献”能否提升长期使用。

以下保留 P3：Claude／Cursor／Gemini 等更多助手、用户明确选择的本地模型、其他操作系统、独立手机客户端、跨设备记忆／配置恢复、在线作品社区、排行榜和商城。跨设备同步须另定离线冲突、身份与删除传播规则；QQ 手机入口不等于跨平台客户端，默认本地可用不应依赖云账号。

数据式角色／行为／台词包与可执行代码插件分开。可先开放固定事件和动作映射；通用插件平台、第三方工具和任意代码能力另行评估，不能随素材导入自动执行。导入模型推荐文字不等于授予账户或调用额度。

## 14. 实施顺序、验收与完成定义

### 14.1 分阶段建议

| 阶段 | 交付范围 | 前置与退出条件 |
| --- | --- | --- |
| A：P0 基线与隔离 | 现有三宿主／两种 QQ 连接真实补验；身份与任务权限、元数据来源规则；非本人通道默认关闭 | 未通过隔离前不得开放公共回复，验证缺口单独记录 |
| B：P1 工作与本人互动 | 宠物旁任务列表、模型／强度／阶段耗时、全用途策略、待处理箱、本人 QQ 角色联动，固定动作按选定范围接入 | 每项能追到真实来源，固定动作无模型调用，现有任务及审批不回归 |
| C：P1 记忆与创作基础 | 按范围存原文／索引／关联、预算与管理；自定义角色、动作绑定、预览和包回导 | 先满足记忆隔离与删除，再启用检索；包不具有脚本／电脑权限 |
| D：P2 内容贡献与便利 | 启动编辑、事件语音、GitHub 一键投稿、审核素材库；按实际需求选快捷工具和提醒 | 投稿有真实上传和审核状态，第三方账号和公开发布需用户动作 |
| E：P2／P3 陪伴及生态 | 共同经历、角色连续反应、窗口／键鼠、多宠、更多助手／平台／同步 | 根据前期使用数据与反馈选择，不将全部候选塞入同一版本 |

任务面板与编辑器可独立拆分，公共权限、模型事实和记忆边界保持一致。公开模式和投稿属于外部行为，需要在产品流程中由用户明确启用或点击提交；本规划文档本身不触发任何外部动作。

### 14.2 必须保留的验收层次

1. 代码与相关自动检查：覆盖身份、范围、模型选择、记忆过滤、包解析、重复消息与失败恢复。
2. 本机真实窗口：中英、深浅配色、展开／收起、拖拽、焦点、混合缩放、多屏、媒体、声音和清理。
3. 宿主与账号：Codex、WorkBuddy、Harness 及两种 QQ 连接分别确认，合成模型／假传输不替代真实回合。
4. 权限攻击与数据隔离：非本人后端直调、跨联系人／群、历史注入、恶意素材、凭据和路径泄露。
5. 内容与投稿：导出回导、本地试演、实际上传、维护者复验及已收录包下载；本机验证通过不自动等于收录。
6. 长期运行：空闲／动画／多任务采样、内存与后台活动、隐藏和休眠恢复、断线重连；用实测描述低占用，不用最低系统配置冒充运行占用。

相关检查按改动风险执行，不因文档或普通局部改动默认全量构建。每项交付记录实现、局部验证、真实宿主、真实 QQ、桌面及用户确认的实际证据，缺失条件明确保留。

### 14.3 开发前需核实的具体问题

- WorkBuddy／Harness 逐次模型及强度的数据源与覆盖能力，尤其当前 ACP 不支持的部分。
- 各 QQ 渠道多模态、主动推送窗口和频率；NapCat 指定版本的账号／协议及许可条件。
- 非本人无工具聊天生成接口与受限记忆服务；公开角色输出可以表现到桌面的范围。
- 任务正文、标题、产物和进展事件的数据来源与授权，不能为了丰富列表全盘读取会话内容。
- 自定义媒体支持格式、转换方式、资源上限、音频混音及真实透明播放；不沿用启动片限制冒充所有作品包规格。
- GitHub 桌面授权、普通投稿者 fork／PR／Release 上传、大包限额和正式素材保存链路。
- 实际 token 预算、检索质量、摘要更新频率及使用者可理解的记忆管理；用合成数据与真实授权场景确定参数。

这些问题进入对应任务的前置核查；已具备的功能继续复用，不因新增规划建立并行的权限、任务、素材目录或模型系统。

## 15. 维护方式

本规划负责功能目标、优先级和验收要求；[维护文档](maintenance.md) 负责当前操作、兼容范围和验证记录；[素材投稿规范](animation-contributions.md) 负责当前可执行投稿流程；README 只介绍已经可用的产品功能。后续实施时同时更新登记表、相关当前说明和验证记录，未实施项保持规划状态。

发生范围变化时记录新增决定及其影响，保留已确认的 QQ 权限、模型真实性、记忆隔离、用户素材及人工收录边界。不得用路线图勾选、静态页面、测试数量或某个依赖的功能清单替代完成证据。
